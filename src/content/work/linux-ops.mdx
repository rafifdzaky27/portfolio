## Situation

The team's production services run on Linode VPS hosts. Someone has to create them, point domains at them, keep certificates valid, control who logs in, patch and back them up, and look first when a service stops answering. That's my job next to the pipelines.

## What I handle

<div class="table-scroll">

| Layer | Work |
|---|---|
| Servers | New VPS from scratch (OS, users, PHP-FPM, Node, Docker). Resizing or splitting hosts based on the dashboards, and sizing plans to real usage to keep cost down. |
| Edge | Domains and DNS records, SSL certificates and renewals, Nginx, Apache and Caddy virtual hosts. |
| Access | SSH keys and permissions on servers and platform accounts, granted on joining and removed on leaving. Firewall rules, fail2ban, SSH config and OS patches. |
| Secrets | Per-environment `.env` files and GitHub Actions secrets, kept out of repositories. |
| Data | PostgreSQL and MySQL users and grants. Database dumps, server snapshots and restores. |
| Processes | PHP-FPM pools, cron and the Laravel scheduler, queue workers and Horizon under Supervisor, log rotation. |
| Docs | The deployment SOPs and workflow docs developers release with. |

</div>

## When a service is down

I work from the outside in:

1. Reachable at all? DNS, certificate, port, web server.
2. Process up? PHP-FPM, the container, Supervisor.
3. What do the logs say?
4. Config, secrets and cached settings correct?
5. Can it reach the database and Redis?

For incident handling, see the [monitoring case](/work/monitoring).

## Limits

This is VPS operations, not a high-availability or multi-region platform. AWS, GCP and Kubernetes are on my learning path, not in my work experience.
